# Reporting and Outputs

ARIA reports are generated by `NarrativeAgent`, but the report should be driven
by structured outputs, not model imagination.

## Report Contract

A report section may state that an analysis was completed only when structured
results exist for that analysis. Missing, skipped, or failed analyses must stay
visible as warnings or limitations.

Examples:

- pseudobulk DE is present only if `pseudobulk_de` contains successful group
  and comparison blocks;
- pathway enrichment is present only if ORA/GSEA outputs exist;
- trajectory is present only if PAGA/DPT results exist;
- LIANA communication is present only if interaction tables exist;
- annotation confidence must reflect CellTypist/fallback status.

## Narrative Kernel

As of `v4.5.2`, `NarrativeAgent` composes supported modalities through a
small kernel under `aria.agents.narrative`.

- `NarrativeBlock` is the unit of report evidence. A successful block must
  have a claim and at least one evidence item.
- `ModalityNarrator` plugins convert agent outputs into blocks. scRNA and bulk
  RNA have first-class narrators; unsupported modalities fall back to the
  legacy renderer until their narrators exist.
- Validators enforce report integrity before rendering: missing successful
  evidence fails, failed analyses must explain the failure, low-confidence
  findings stay visible, causal language is downgraded unless causal evidence
  is explicit, PAGA/DPT receives an exploratory caveat without velocity or
  time-course support, and referenced figures/tables must exist at render time.
- `methodology.json` persists the serialized narrative blocks so a reviewer
  can audit claims, evidence, caveats, metrics, figures, and tables outside
  the HTML.

## Main Outputs

| Output | Purpose |
|---|---|
| `report.html` | Self-contained interpretation and methods |
| `figures/` | UMAPs, volcano plots, heatmaps, pathway plots, trajectory plots |
| `tables/` | Supplementary TSVs for DE, pathways, annotations, communication, trajectory |
| parameter decisions | Thresholds and selected analysis parameters |
| warnings | Missing dependencies, skipped analyses, QC caveats, low confidence claims |

## scRNA Supplementary Tables

When available, scRNA reports can export:

- QC per-sample metrics;
- cell-type or cluster annotation tables;
- marker genes;
- pseudobulk DE summaries;
- pseudobulk DE gene tables;
- pathway enrichment tables;
- LIANA interaction tables;
- PAGA connection tables;
- DPT pseudotime summaries.

## Methods Section

Methods should include:

- organism and genome assembly when known;
- input data type and preprocessing path;
- QC thresholds;
- normalization and clustering parameters;
- integration method and batch column;
- DE model and design formula;
- covariates;
- pathway databases;
- skipped analyses and reasons.

## Confidence and Caveats

ARIA uses four confidence levels:

- `HIGH`: strong structured evidence;
- `MEDIUM`: plausible evidence with caveats;
- `LOW`: weak, partial, or conflicting evidence;
- `INSUFFICIENT`: not enough evidence to support a claim.

Reports must not hide `LOW` or `INSUFFICIENT` findings.

## Marker Fallback Labels

If CellTypist is unavailable and ARIA uses marker-panel fallback labels, the
report must warn that labels are curation targets. Downstream trajectory,
communication, and pseudobulk sections should describe results as cluster or
marker-label results rather than definitive cell identities.
