## 2. Qué se hizo en v4.3.10 — manual de los 6 fixes

La sesión 2026-05-12 nació de un report de 29 KB que el TUI escupió tras la primera
corrida wallclock real con datos scRNA reales (hippo 4 samples). El triage del HTML
expuso 6 bugs latentes desde la refactorización multimodal v4.3.5. Los detallo
con suficiente contexto para que cualquiera entienda el patrón sin re-leer commits.

### B1 — DesignAgent groups respeta young/old (no filename-per-group)

- **Síntoma:** El Parameter Decisions Log mostraba `{"hc1265": [...], "hc77": [...], "hc11": [...], "hc1153": [...]}` — un grupo por filename. Consecuencia downstream: `_needs_pseudobulk` correctamente rechazó porque no había ≥2 reps por grupo, y pseudobulk DE **nunca disparó** pese a que el prompt pedía aging comparison.
- **Raíz:** `_propose_groups` en `aria/agents/design_agent.py` enviaba al LLM solo los stems de archivo (hc11, hc77, ...) sin la pregunta biológica. Con donor barcodes opacos, el LLM no podía inferir la mapping young↔old. Y el CP solo ofrecía `Confirm / Re-infer / Edit names (using defaults) / Cancel` — sin opción para que el usuario inyectara el mapping manualmente.
- **Fix (commit `2b7ab63`):**
  1. `_propose_groups` ahora incluye `biological_intent.question` (o `comparison`) en el prompt. Le instruye al LLM que si los filenames no portan señal del contraste, devuelva un único grupo `all` con confidence='low' (sin fabricar grupos espurios).
  2. CP groups options agregó `"Other — manually assign groups (e.g. young=hc1153,hc1265; old=hc11,hc77)"`. El TUI ya tenía detección de "Other —" (ver `aria/tui.py:208`) que dispara un free-text follow-up, así que no hubo que tocar el TUI.
  3. Nuevo `_parse_manual_groups(text)` — soporta JSON (`{"young":["hc1153","hc1265"]}`), `k=v;k=v` (`young=hc1153,hc1265; old=hc11,hc77`) y `k:v|k:v`. Tokens se separan por coma/espacio.
  4. Nuevo `_normalise_manual_groups(proposed)` — para cada token typed por el usuario hace primero exact match contra `self._parsed_samples[*].stem`, luego substring match. Tokens sin match se loguean y se descartan (no se fabrican grupos).
- **Cómo usarlo en el CP:**
  Cuando el LLM no infiere bien, el usuario elige opción 3, el TUI pregunta "Value", el usuario teclea (ejemplo):
  ```
  young=hc1153,hc1265; old=hc11,hc77
  ```
  El parser bind `hc1153` → `GSE278576_hc1153_raw_feature_bc_matrix`, etc.

### B2 — NarrativeAgent TUI path no llamaba generate_figures()

- **Síntoma:** `figures/` vacía, `report.html` = 29 KB (esperado en v4.3.5: 5.9 MB self-contained). El report tenía las tablas inline (DPT, PAGA, LIANA) pero **cero PNGs** embebidos.
- **Raíz:** `_narrative_scrna.generate_figures(findings, h5ad, output_dir, env_manager)` existe desde v4.3.5 — orquesta UMAPs (subprocess en `aria-rna-env` via `rna_figure_umap.py`) + DE bar (in-process) + pathway dotplots (in-process via `rna_pathway_viz.make_ora_dotplot`) + cellcomm heatmap/barplot + trajectory PAGA. Solo el harness `--emit-html` lo llamaba; el `NarrativeAgent.run()` del orchestrator/TUI path nunca lo invocaba. `build_scrna_html_section` leía `findings.get("figures")` — vacío en TUI.
- **Fix (commit `1ed8f3d`):**
  1. Extraje `_build_report_dir(experiment_id, intent, exp_ctx)` desde el medio de `_render_html_report` — construye `~/.aria/reports/aria_<ts>_<slug>_<suffix>/{figures,tables}/` y lo retorna. Idempotente.
  2. Nuevo `_generate_scrna_figures(agent_results, report_dir)`:
     - Importa `aria.utils.environment_manager.env_manager` (singleton global de la utility — el orchestrator no necesita propagarlo).
     - `findings = unwrap_scrna_findings(sc)` → muta este dict; downstream lo lee por referencia.
     - Llama `_narrative_scrna.generate_figures(findings, h5ad, report_dir/"figures", env_manager)`.
     - Falla silenciosa solo loguea + sigue (no rompe HTML).
  3. `NarrativeAgent.run()` ahora:
     - Construye `report_dir` ANTES de escribir secciones
     - Llama `_generate_scrna_figures`
     - Pasa `report_dir` a `_render_html_report` (que cae back a builder propio si llega None — backward compat).
- **Verificación esperada en v4.3.10:** `report.html` ≥ ~3-6 MB (depende de cuántas pathway dotplots se rendericen) con UMAPs base64 inline, DE bar, top pathways dotplots.

### B3 — Multi-sample QC emitía sólo `n_cells_total`

- **Síntoma:** En el report aparecía `"scRNA-seq | ? → ? cells"` en la QC table. El template lee `qc.n_cells_before` / `qc.n_cells_after`.
- **Raíz:** En `scrna_agent._run_qc` la rama multi-sample (`if len(files) > 1`) retornaba `{n_samples, n_cells_total, n_genes_shared, per_sample, batch_col}` — sin `n_cells_before` ni `n_cells_after`. La rama single-sample (`_qc_single`) sí los tiene porque `rna_qc.py` los emite.
- **Fix (commit `6d4975a`):**
  1. `per_sample` entries ahora incluyen `n_cells_before` (junto a `n_cells_after` y `pct_removed` que ya tenían).
  2. Al final del multi-sample QC, sum-aggregate sobre `per_sample`:
     ```python
     n_before_total = sum(p["n_cells_before"] for p in per_sample)
     n_after_total  = sum(p["n_cells_after"]  for p in per_sample)
     pct_removed    = round(100*(n_before-n_after)/n_before, 2)
     ```
     Y se emiten al top level del retorno (junto a `n_cells_total` que se preserva).
- **Verificación:** QC table debe mostrar `"scRNA-seq | <N> → 22136 cells · ~X% removed"`.

### B4 — Annotation findings dumpeaba dict crudo

- **Síntoma:** El findings card scRNA tenía literalmente
  ```
  (top: {'cell_type': 'Astro GFAP AQP1', 'celltypist_label': 'Astro GFAP AQP1',
   'agrees_with_celltypist': True, 'confidence': 'high', 'rationale': '...',
   'key_markers': ['SORBS1', 'GLIS3', ...]}, {'cell_type': '...'}, ...)
  ```
- **Raíz:** `summarize_scrna_text` en `_narrative_scrna.py` hacía `unique = sorted({str(v) for v in ct.values()})`. En v4.3.5 esto era seguro porque `cell_types` era `{cluster_id: "label"}`. Tras la integración del LLM rationale para anotación (no recordé la versión exacta — ver git log de `_annotate_cell_types`), la estructura mutó a `{cluster_id: {cell_type, celltypist_label, rationale, key_markers, ...}}` y `str(dict)` dumpeó el dict completo como cadena.
- **Fix (commit `4510f2b`, primera mitad):** Helper local `_label(v)`:
  ```python
  def _label(v):
      if isinstance(v, dict):
          return v.get("cell_type") or v.get("celltypist_label") or v.get("label") or ""
      return str(v) if v else ""
  unique = sorted({_label(v) for v in ct.values() if _label(v)})
  ```
  Tolera ambas shapes (legacy str + nueva dict).

### B5 — Methods "resolution=? across ? candidates"

- **Síntoma:** Methods section del report tenía literalmente `"Leiden clustering at resolution=? (selected by silhouette across ? candidates) yielded 8 clusters."`
- **Raíz:** `build_scrna_methods` leía `cdec.get("recommended")` y `cdec.get("n_candidates")`. Pero `scrna_agent.py:125-129` emite `clustering_decision = {resolution, justification, n_clusters}`. Las keys `recommended`/`n_candidates` **nunca existieron** en la shape real — eran reliquia de un schema imaginado.
- **Fix (commit `4510f2b`, segunda mitad):**
  ```python
  res = (cdec.get("resolution")        # canonical
         or cdec.get("recommended")    # legacy schema (never populated)
         or clu.get("resolution"))     # fallback within clustering itself
  n_cand = cdec.get("n_candidates")
  cand_str = (f" (selected by silhouette across {n_cand} candidates)"
              if n_cand else "")
  ```
  El clause de candidates se omite cuando falta el dato (en vez de imprimir "?").

### B6 — DPT root selection elegía mal (mature Oligo en vez de OPC)

- **Síntoma:** El report mostraba pseudotime ordering: `Oligo MOG OPALIN (0.007) → Micro → Astro → OPC PDGFRA PCDH15 (0.42) → ... → InN VIP EXPH5 (0.92)`. Biológicamente inverso: OPC es progenitor, Oligo es destination.
- **Raíz:** `rna_trajectory.py` línea 119 fallback heuristic: `adata.obs["n_genes_by_counts"].values.argmin()` (cell con menos genes detectados = "least complex"). En hipocampo adulto, los Oligo maduros tienen menos genes activos que OPCs proliferativos, así que la heurística elige mature cell types como root.
- **Fix (commit `bed3dc7`):** Tercer nivel de preferencia entre el explicit `root_cell_type` (preferido) y el fallback min-complexity (último recurso):
  ```python
  PROGENITOR_TOKENS = ("opc","nsc","npc","rgl","rg ","gmp","mpp","hsc",
                       "stem","progenitor","precursor")
  # Tras intentar root_cell_type explícito, antes de fallback:
  for lab in cell_types:
      if any(tok in lab.lower() for tok in PROGENITOR_TOKENS):
          # Largest matching cluster wins (statistical power)
          n = (adata.obs[cell_type_col] == lab).sum()
          if n > best_size:
              best_label, best_size = lab, n
  ```
  Report ahora dice `"root_used": "auto (progenitor match: OPC PDGFRA PCDH15)"` — auditable.
- **Cobertura:** Funciona para neural lineages (OPC/NSC/NPC/RGL), hematopoyesis (HSC/MPP/GMP), y cualquier cell type que contenga `progenitor/precursor/stem` en su label. No cubre desarrollo temprano con labels Cluster_N — para eso pasar `root_cell_type` explícito desde el harness.
